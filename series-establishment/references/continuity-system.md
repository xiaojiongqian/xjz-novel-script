# Continuity System

Use this reference for readiness audits, approved changes, reusable templates, and maintenance after comic-episode or picture-book production begins.

## Canon registers

Maintain authoritative ledgers for character names and aliases, location hierarchy, object counts and ownership, timeline anchors, production-unit knowledge boundaries, relationships, power rules and costs, visual anchors, open loops, reveals, and future seeds. One fact should have one canonical source even if summaries repeat it elsewhere.

## Impact matrix

| Changed fact | Typical affected artifacts |
|---|---|
| Character name or relationship | overview, outline, character bible, prompts, continuity rules, templates, reports |
| Setting or era | overview, world bible, outline, costumes, location prompts, negative prompts |
| Power rule | world bible, episode solutions, abilities, continuity gate |
| Project form | overview, Chinese usage guide, active script template, report template, production checks |
| Season/book-cycle or objective count | overview, outline, ledgers, reports, progress templates |
| Character visual anchor | art bible, solo prompts, group prompts, visual checklist |
| Location identity | world bible, outline, location libraries, reports |

Search globally for deprecated values after updates. Preserve completed scripts unless the user explicitly includes them.

## Pre-script continuity gate

- Does the episode or book promise match the locked outline?
- Does the active template match the locked comic or picture-book form?
- Is every character allowed to know what they act on?
- Do names and location labels match the registries?
- Do objective counts and ownership enter correctly?
- Does the solution obey world and power rules?
- Is required mascot or companion presence accounted for?
- Do costumes and locations match the art bible?
- Is any future reveal exposed early?

## Post-production-unit writeback

After an episode or book is approved:

1. Create a concise report in the project's chosen reporting language.
2. Summarize without adding events absent from the script.
3. List every on-screen character, including unnamed groups.
4. List every shown location; mark established key-art locations and page/panel or page/spread coverage.
5. Update progress, counts, ownership, relationships, confirmed information, and the ending hook.
6. Add only stable events to canon ledgers.
7. Record new obligations or open loops.

## Readiness audit

Classify findings as `blocker`, `major`, `minor`, or `candidate`. Audit causes, not just filenames: a document can exist and still fail its responsibility.
